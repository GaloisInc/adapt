# Generating Concepts with FCbO and analyzing the concepts

##Brief description of the files (to be found in the explore directory)

The current implementation the FCA analysis is contained in fcbo_core.py (port of the original FCbO C implementation) and fca_script.py (script to launch the concepts generation with FCbO and analyze the generated concepts to find anomalies).  
Example input files are provided in the directory: context files (one in CXT and one in FIMI format obtained by using the event query on ta1-theia-bovia-cdm17.bin) as well as json specification files (event query in spec_context_event.py, netflow query in spec_context_netflow.py and file execution query in spec_context_execute.py)

## Launching the concept generation and analysis


The concept generation and analysis can be launched after an avro file has been ingested by invoking the following command:
```
python3 fca_script.py [-h] [--inputfile/-i INPUTFILE] [--specfile/-s SPECFILE][--min_support/-m MIN\_SUPPORT] [--disable\_naming/-dn] [--outputfile/-o OUTPUTFILE] [--analysis/-a]
```

The command requires either the INPUTFILE or the SPECFILE to be supplied, otherwise an error is thrown. 
INPUTFILE corresponds to an input file (context) in either the CXT or FIMI formats. SPECFILE is a json file, whose name contains the string 'spec' (this is likely to change in a later version),
that specifies how to generate an input context for FCbO, based on a query and strings naming the objects and the attributes (an example of specification file is the spec_context_event.json file).
If only INPUTFILE is provided, the context in the file is used as input to FCbO. If only SPECFILE is provided, a query is sent to the database to generate a temporary context that is used as input to FCbO. If both INPUTFILE and SPECFILE are provided, a query is sent to the database to generate a context that is saved to the input file. The input file is then used as input to FCbO. In all cases (likely to change in future), full paths are expected.

MIN_SUPPORT is a number between 0 and 1 that corresponds to the minimal support value for a concept to be generated by FCbO divided by the number of objects. By default, this value is set to 0, which means all concepts are generated.

The --disable-naming/-dn flag cannot be invoked with an input FIMI file. It can be only invoked with a json query specification file (SPECFILE) or an input file in CXT format. If invoked, the objects and attributes are identified by their positions in the context matrix (as is the case for FIMI files) and not by name.

OUTPUTFILE specifies where to save the FCbO concepts (full path expected). By default, the concepts are just printed out on the screen.

The --analysis/-a flag specifies whether or not to analyze the concepts after their generattion with FCbO.


To perform an analysis equivalent to the one obtained with ```python3 analyze.py --event```, one could launch:
```
python3 fca-script.py -s spec_context_event.json -m 0.05 -a
```

The equivalent of ```python3 analyze.py --netflow``` is:
```
$python3 fca-script.py -s spec_context_netflow.json -m 0.05 -a
```
